# 画面のスモークテスト

環境にあるPlaywrightと、その版に同梱されたChromiumを使用する。リポジトリへのパッケージ追加は不要。

```sh
node ui-tests/smoke.js
```

ポート8000で起動している画面を使う。画面幅と高さは `UI_TEST_WIDTH` と `UI_TEST_HEIGHT` で変更できる。未起動なら、テストが `python3 -m http.server` を起動し、終了時にそのサーバーだけを止める。別のURLは `UI_TEST_URL` で指定できる。

既定の390×844で、タイトル→ひとりで遊ぶ（標準設定・CPUつよい）→カード説明→兵士を出す→ターン終了→結果→再戦を確認する。操作はフォーカスとEnterを使用。デバッグの公開APIは状態と出せるカードを読むためだけに使い、Gameの状態や手札を変更するメソッドはテストから呼ばない。起動直後は既存のデバッグ起動を経て、メニューからタイトルへ戻る。

演出速度だけを検証中に短縮する。コンソール／ページエラー、描画同期警告、結果の手番数・使用カード数を確認し、失敗すると終了コード1になる。

画像と結果は `ui-tests/artifacts/` に生成し、Gitには入れない。失敗時は `failure.png` と `failure.json` を見る。

Playwrightのブラウザ配置を環境で変えている場合は `PLAYWRIGHT_BROWSERS_PATH` を使う。必要な環境だけ `UI_TEST_CHROMIUM` で同梱Chromiumの実行ファイルを指定できる。

実機タッチ・音の聴き心地・初見の人の理解・オンラインの通し対戦・全画面幅は、このスモークテストの対象外。

## デッキ編成

`node server/server.js` を起動し、`node ui-tests/deck-editor.js` を実行する。390×844 と 360×640 で旧版デッキの読み込みと修正、編成・保存・複製・削除、偏光、同じ端末とオンラインでの対戦開始を確認する。オンラインでは再接続後も自分のデッキを表示できるか確かめる。画面と偏光の連続画像は `ui-tests/artifacts/` に出力する。

## 天候

`node ui-tests/weather.js` を実行する。390×844 と360×640で7種類の背景と画像、天候の説明と残り周回、警報の色、落雷、呪文で変わった天候と演出スキップを確かめる。2つ目のサイズでは「動きを減らす」も検証する。画像は `ui-tests/artifacts/` に出力する。

## 日本バージョン

`node server/server.js` を起動し、`node ui-tests/japan.js` を実行する。タイトルの「日本」で切り替わること（図鑑が「妖怪」になる）、日本の城（仮の絵）、自分の忍者は見えて相手の忍者は盤面に出ないことを確かめる。

## スマホの代わりの確認（オフライン・長押し拡大）

`node server/server.js` を起動し、`node ui-tests/device.js` を実行する。
- オフライン：iPhone 13 の大きさで開き、サービスワーカーが配るファイルをしまい終わってから通信を切り、読み直して「ひとりで遊ぶ」を始められるか・絵が欠けないかを確かめる（初回は保存に30秒ほどかかる）
- 長押し拡大：iPhone SE・iPhone 13・Pixel 7 の大きさとタッチで、デッキ編成のカードを長押しして拡大し、指を離してもカードが足されないこと、端末の傾き（`deviceorientation`）で光と角度が動くこと、カードが画面に収まることを確かめる

ホーム画面に追加する操作・iPhone の「動きと向き」の許可の確認・指の感触は、実機でしか分からないので対象外。
