# 台帳 → cards.json の取り込み（四大陣営 PR-B）

台帳（`../CASTLE_FIELD_4陣営_全295カード台帳_v1.0.json`）のカードを、`data/cards.json` のカード定義にする道具と対応表。
PR-B は陣営ごとに分けて進める：**B1＝王国軍・全陣営共通・森の同盟の武器**（済）、**B2＝森の残り**（済）、B3＝魔族軍、B4＝竜族帝国。

## ファイル

| ファイル | 中身 |
|---|---|
| `mapping.mjs` | **対応表**。台帳の1行（1枚）ごとに、種類（`kind`）・効果（`effect`）・数値・役割（`role`）・実装の有無（`implemented`）とその理由（`reason`）・図鑑のストーリー（`story`）を決める。取り込む範囲は `SCOPE` |
| `build.mjs` | 生成スクリプト。対応表と台帳から、下の4つを書き出す |
| `table.md` | 対応表の一覧（自動生成。レビューはこれを読むのが早い） |

書き出すもの（`node docs/four-factions/import/build.mjs`）：

- `data/cards.json`：新規カードの追加・更新（末尾に台帳の順で並ぶ）。既存カードは、対応表で `rename`（名前を台帳の名前にする）・`relink`（合成先を台帳の `next_name` にする）を付けた行だけ変える。**既存カードの効果・数値・IDは変えない**
- `data/shop.json`：新しい兵士（`skin_<ID>`）・魔法（`fxskin_<ID>`）のスキン（`tests/economy.test.js` の「全キャラ・全魔法に1つずつ」）
- `js/ui/stories-factions.js`：新しいカードの図鑑のストーリー（`js/ui/stories.js` の `CARD_STORIES` に混ぜる）
- `table.md`

**冪等**：何度実行しても同じ結果。`--check` を付けると書き出さずに、今のファイルと一致するかだけ確かめる（違えば終了コード1）。
`tests/four-factions-b1.test.js` も、作り直した結果が今のファイルと同じかを確かめる。数値やストーリーを直すときは `mapping.mjs` を直して作り直す（`cards.json` などを手で直さない）。
作り直したら `node js/ui/build-precache.js` も実行する（`stories-factions.js` が配るファイルなので）。

## ID の規則

- **既存カード**（台帳の「既存」「改名」）：今のIDのまま（対応表の `id`）。改名しても ID は変えない
- **新規カード**（台帳の「新規案」）：`<chain_id>_<rarity>`（例：`king_cavalry_legendary`）。`build.mjs` が、既存のIDとぶつかったら止まる
- 台帳で `chain_id` が空の行は8行あり、どれも「既存」（身代わり・反射・ピュリファイ・フレア・シールド・ブラスト・適応・天の恵み・ゲイルフォース・魔力強奪）なので、新しいIDはいらない。新規案で `chain_id` が空の行が出たら、`build.mjs` が止まる（規則を決めてからここに書く）

## 機械的に付けるもの

- `faction`：王国軍＝`kingdom`、森の同盟＝`forest`、魔族軍＝`demon`、竜族帝国＝`dragon`、全陣営共通＝`common`
- `element`：台帳の属性（火＝`fire`・水＝`water`・風＝`wind`・土＝`earth`・氷＝`ice`・雷＝`thunder`・闇＝`dark`・光＝`light`・混沌＝`chaos`・無／空＝書かない）。**武器と魔法だけ**に書く（兵士に属性を持たせるスキーマはまだない。兵士の属性は対応表の `note` に残す）。複数の属性（ドルイド系の「火・水・風・土」、「水・生命」、「土・植物」）の行は、対応表で `multiAttribute: true` にしたときだけ通る（`element` は書かない。B2）
- `rarity`：台帳のまま。`fuseTo`：台帳の `next_name` のカード（なければ、レジェンド・スペシャルは書かず、それ以外は `null`＝合成しない）
- `count`：0（共有山札は排出率で作るので使わない）。`weight`：兵士はコモン1・アンコモン0.75・レア以上0.5、それ以外は1
- `factionOnly: true`：台帳から足したカードは、**陣営モードの候補でだけ引き当てる**（陣営なしの山札・運命の祈り・幸運の加護・入手券・魔物のごほうびには出ない。陣営なしのモードの結果を変えないため）。デッキ編成（カスタム）には、効果のあるものなら入れられる（仕様：カスタムデッキは陣営の制限なし）

## implemented の決め方

- **true**：今のコードのしくみで、その効果が**実際に戦闘で効く**とき（例：光の攻撃魔法＝`damageEnemySoldiers` に光属性。武器＝攻撃補正と属性。進む兵士）。テスト（`tests/four-factions-b1.test.js`）で実際に動かして確かめる
- **false**：仕様の効果を起こすしくみがまだないとき。既存の別の効果で代用して「実装済み」にはしない（仕様 PR-B）。`effect` を省略して、`effectPlan`（将来の効果の説明。数値は仕様の仮値）・`description`（画面に出す文。「【準備中】」で始める）を書く。`implementationNote` に理由を入れる
  - false のカードは、どのモードでも引き当てない・デッキ編成に入れられない・手札に来ても出せない（「このカードの効果はまだありません」）・合成の元にも合成先にもならない
- B1 で false にしたもの：**聖術師系5枚**（浄化・守護の効果も、兵士に光属性を持たせるスキーマもない。ふつうの魔法使いとして出すと代用になる）、**カウンター5枚**（防御の場面で軽減・無効・反撃を起こすしくみがない）。どちらも PR-C で作る
