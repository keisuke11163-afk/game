# アカウント・保存の基盤（Phase 1）

オンライン対戦のサーバー（`node server/server.js`）に、アカウントと永続データを足した。**サーバーが唯一の正しい情報源**。
画面のファイルだけを配る `python3 -m http.server` では、アカウント機能は出ない（今までどおり遊べる）。

## 起動と設定（環境変数）

| 名前 | 意味 |
|---|---|
| `CF_DB_PATH` | データベースのファイル（既定 `data-store/castlefield.db`。`.gitignore` 済み） |
| `CF_PUBLIC_URL` | 公開URL（例 `https://game.example.com`）。OAuth の戻り先に使う。`https://` ならクッキーに `Secure`・`__Host-` が付く |
| `CF_TRUST_PROXY=1` | リバースプロキシの後ろのとき。`X-Forwarded-For`（IP）と `X-Forwarded-Proto`（https 判定）を信じる |
| `CF_SECURE_COOKIES=1` | `CF_PUBLIC_URL` が https でなくても、クッキーを Secure にする |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google ログイン |

**秘密鍵・クライアントシークレットはリポジトリに入れない**（環境変数か、ホスティングの秘密管理で渡す）。

### 外部での設定が必要なもの（このリポジトリの外）
- Google Cloud Console：OAuth クライアント（ウェブ）を作り、承認済みのリダイレクト URI に `{CF_PUBLIC_URL}/api/auth/oauth/callback/google` を登録
- Apple ログインはなくした（Apple Developer Program が有料のため。人間の指示）。代わりにメールアドレスとパスワードで登録できる（外部の設定は要らない）
- Google は HTTPS の公開URLが必要。未設定のサーバーでは、画面の連携ボタンは「このサーバーでは未設定」と出て押せない

### HTTPS の中継（リバースプロキシ）の後ろで動かすとき
オンライン対戦（部屋・ランクマッチ）の知らせは、サーバーから送り続ける通信（Server-Sent Events、`GET /api/stream`）で届く。中継がこれを溜め込むと、**「同じ合言葉なのに相手が見えない」「ランクマッチで相手が見つかったのに対戦に移らない」**になる。
- サーバーは `Cache-Control: no-cache, no-transform` と `X-Accel-Buffering: no` を付け、最初に2KBの空のコメントを送り、15秒ごとに ping を送る（中継が溜め込まない・切らないように）
- **nginx**：`/api/stream` で溜め込みを切る。`proxy_set_header Host $host;` も要る（書き込みの送り元の確認のため）
  ```
  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Connection '';
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1h;
  }
  ```
- **Caddy**：`reverse_proxy 127.0.0.1:8787` だけでよい（SSE はすぐ流す）。圧縮（`encode`）を付けるなら `text/event-stream` を除く
- **Cloudflare（Tunnel・プロキシ）**：名前つきのトンネル（Cloudflare のアカウントで作る）なら、ふつうはそのまま流れる。届かないときは、キャッシュのルールで `/api/*` をキャッシュしない（Bypass）にする
- **Cloudflare のクイックトンネル（`cloudflared tunnel --url …`・`*.trycloudflare.com`）は SSE に対応していない**（溜め込まれる）。それでも遊べるように、画面は SSE で4秒なにも届かなければ、**ロングポーリング（`GET /api/poll?token=…&after=N`）に自動で切りかえる**（このタブでは次から最初からロングポーリング）。中身は SSE と同じ。少し遅れることがあり、クイックトンネルは同時に200本までなので、大人数・本番では名前つきのトンネルを使う。URL が起動のたびに変わるので、Google ログインのリダイレクト URI もそのたびに変わる（Google を使うなら名前つきのトンネルにする）

## データベース

SQLite（Node.js 標準の `node:sqlite`。**Node.js 22.13 以上**。外部パッケージなし）。ファイル1つで、今の規模（デッキ・アカウント）にはこれで足りる。
複数台に増やすときは PostgreSQL へ移す（`server/accounts/db.js` の `Db` と SQL がここだけに閉じている）。

- 起動のたびに `MIGRATIONS`（`server/accounts/db.js`）を順に適用する（`schema_migrations` に記録。**適用済みは書きかえず、末尾に足す**）
- 書き込みは `tx()`（`BEGIN IMMEDIATE`）の中。同時リクエストは1つずつ処理され、二重処理にならない
- WAL・`synchronous=FULL`・外部キー有効。アカウントを消すと関連する行は `ON DELETE CASCADE` で一緒に消える
- 保存するもの：ユーザー、外部認証との紐づけ（`provider` + `subject` だけ。**メールアドレスは預からない**）、セッション（ハッシュだけ）、デッキ、設定、監査ログ

### バックアップと復元
```sh
node server/backup.js backup                # data-store/backups/ に日時つきで作る（動いているサーバーがあっても可）
node server/backup.js backup /path/out.db
node server/backup.js restore /path/out.db  # サーバーを止めてから。いまのデータは .before-restore に退避
```
定期実行は cron などで `backup` を呼ぶ（運用側の設定。毎日・世代管理は運用で決める）。

## 認証とセッション
- 初回はゲスト（`POST /api/auth/guest`）。Google を連携するか、メールアドレスとパスワードを登録すると、**同じユーザーのまま** member になる（データ消失・重複登録なし）
- **メールアドレスとパスワード**（人間に確認して決めた。小規模なので**確認メール・パスワードの再設定はない**）
  - 登録：いまのアカウント（ゲストでも Google の会員でも）に1つだけ。同じアドレスは2つのアカウントに登録できない（大文字・全角・前後の空白は同じとみなす）
  - 保存：アドレスはそのまま持たず、見つけるためのハッシュ（SHA-256）だけ（`email_logins.email_hash`）。パスワードは scrypt（N=16384・r=8・p=1、16バイトの塩）のハッシュだけ。8〜128文字
  - ログイン：パスワード違いも知らないアドレスも、同じ理由「メールアドレスかパスワードが違います」・同じくらいの時間で断る（登録されているかを知られないように）。1つのアドレスへの登録・ログインは15分に10回まで（IP ごとの制限とは別）
  - ログインした先のアカウントと、いまのゲストのデータの扱いは Google と同じ（下の確認の画面）。会員でログイン中に、別のアカウントのメールでログインはできない（先にログアウト）
  - パスワードの変更は今のパスワードが要る。変えると、ほかの端末のログインは切れる
  - **パスワードを忘れたら戻せない**（画面にも書いてある）。必要になったら、確認メール・再設定を足す（メールの送信サービスが要る）
- すでに連携済みのアカウントにゲスト（データあり）がログインしようとしたら、確認の画面（`link/resolve`）。「切りかえる」でゲストのデッキは空き枠に移り、相手のデータは消えない。ゲストにデータがなければ確認なしで切りかわる
- OAuth は認可コードフロー。`state`（1回きり・10分）・`nonce`・PKCE（Google）。ID トークンは **サーバーで** 署名（RS256・公開鍵は JWKS）・`iss`・`aud`・`exp`・`nonce` を検証（`alg: none` や別の鍵は拒否）
- セッションの値は256ビットの乱数で、DB にはハッシュだけを保存。Cookie は `HttpOnly; SameSite=Lax`（HTTPS では `Secure` と `__Host-` 付き）。有効期限は、使わなければ30日・最長90日。連携・切りかえのときは作り直し、古いものは失効
- CSRF：書き込みは `X-CF-Client: 1` と、セッションごとの `X-CF-CSRF`（`GET /api/me` で受け取る）が必要。`Origin` が違えば拒否。アカウントのAPIは CORS を許さない
- 回数の制限：IP ごと。認証系 30回/分、そのほか 240回/分（`429` と `Retry-After`）

|---|---|
| `GET /api/me` | `{ user, csrf, providers: { google }, oauthReady }`。`user.providers` は `"google"` / `"email"` の配列。ログインしていなければ `user: null` |

| `GET /healthz` | 稼働確認 |

## 端末のデッキとの関係（`js/ui/Account.js`）
- デッキは端末（`localStorage`）にも残す（オフラインで遊べるように）。変えたらクラウドへ送る（600ms まとめて）
- このアカウントをこの端末で初めて使うとき：端末のデッキを**取り込む**（`import`）。上書きする前の端末のデッキは `cf-mydecks-backup-*` に最新3つまでとっておく
- 起動のたびにクラウドと合わせる。ほかの端末が先に変えていたら（409）、端末の内容はとっておいて、クラウドを採用し、その旨を表示する

## まだやっていないこと（Phase 1 の範囲外）
- 本物の Google での通信の確認（認証情報がないため。テストは、同じ手順・同じ署名の検証をする**テスト用の認証サーバー**で行っている）
- データ引き継ぎのコード（Google かメールアドレスで引き継ぐ）、確認メール・パスワードの再設定
- 古い（使われていない）ゲストの掃除、ログの外部送信、複数台構成

# Phase 2：ホーム・プロフィール・プレイヤーレベル・基本戦績

## 試合の記録（サーバーだけが決める）
- 部屋の試合が決着すると（`Room.finishMatch`）、**ゲームサーバーが確定した勝敗**を `Progress.recordMatch` に渡す。クライアントが経験値・勝敗を申告する口はない
- 部屋に入るとき（`/api/join`）、ログイン中ならその席にアカウントを結びつける（`seat.userId`）。ログインしていない人・CPU の席は、戦績に入らない
- 試合 ID（サーバーが作る UUID）は1回だけ記録する（二重付与なし）。`matches` / `match_players` に保存（`mode_id` は `kingdom`。将来の別モード用）
- **ひとりで遊ぶ・同じ端末はサーバーを通らないので、経験値・戦績の対象外**（クライアントの申告を信じないため）
- 数えない（`counted=0`）：同じアカウントが複数の席にいる試合（ひとり二役での稼ぎ）。経験値が 0：`minTurns`（4手番）未満で終わった試合、試合中に部屋を出た人

## レベル（`data/progression.json`）
- 次のレベルまでの経験値 = `base + growth × (レベル−1)`（60, 80, 100, …）。最大 100。**レベルはランクと独立で、対戦中のカード性能は変えない**
- 経験値：1試合 `base`(20)＋勝利 `win`(15)。相手が人間でなくCPUだけなら `cpuMultiplier`(0.5)倍
- 称号：レベルに応じた自動の称号（`titles`）。ショップの称号は Phase 5
- **レベル報酬**：レベル2以上で、1レベルにつき1回、無料コインを受け取る（`levelReward`）。`wallets.free_coins`（将来の有料通貨は別の列にする）。`level_rewards` の主キーで二重受け取りを防ぐ。コインの使い道（ショップ）は Phase 5

## プロフィールと公開設定（`data/profile.json`）
- アイコンは決まったものから選ぶ。公開設定は `stats`（戦績）・`history`（対戦履歴）・`decks`（使用デッキ）ごとに `public` / `friends` / `private`。**`friends` はフレンド機能（Phase 4）までは本人以外には見えない**
- 既定：戦績は公開、履歴・デッキは非公開
- アカウント削除：自分の戦績・経験値・通貨は消え、相手の戦績に残る自分の名前は「（削除済み）」になる

## API（Phase 2）
| メソッド・URL | 内容 |
|---|---|
| `GET /api/home` | ホーム用のまとめ（`level`、`coins`、`deck`、`stats`、`rewardsAvailable`、`icons`。`rank`/`season` は Phase 3 まで `null`） |
| `GET /api/profile/me` ／ `GET /api/profile/user/{userId}` | プロフィール（他人は公開設定の範囲だけ） |
| `POST /api/profile/settings` `{ icon?, privacy? }` | アイコン・公開設定 |
| `GET /api/history?limit=` | 自分の対戦履歴と、直近1試合（経験値・レベルアップの表示用） |
| `GET /api/level-rewards` ／ `POST /api/level-rewards/claim` `{ level }` | 受け取れる報酬／受け取る |

## 画面
- アカウント機能があるサーバーでは、**ホーム画面が入口**（`js/ui/Home.js`）。「対戦開始」は今までのタイトル（モード選択）へ進む。タイトルの「ホームへ」で戻る
- 未実装の機能（ランクマッチ・フレンド・ショップ・ガチャ・スキン・ミッション・ランキング）は、「準備中」と出して押せない
- プロフィール（`ProfileView.js`）、試合のあとの経験値・レベルアップ（`Progression.js`。オンライン対戦の結果画面）
- アカウント機能のないサーバー（python の簡易サーバーなど）では、ホームは出ず、今までのタイトルのまま

# Phase 3：ランク・MMR・マッチメイキング・シーズン・不正対策

**数値はすべて仮**（`data/ranks.json`・`data/seasons.json`。サーバーを再起動すれば反映）。

## ランク
- 9階級（低い順）：Iron・Bronze・Silver・Gold・Platinum・Diamond・Ascendant・Immortal・Radiant。Iron〜Ascendant は I〜III のディビジョン。Immortal・Radiant は **RP が 2400 以上で、シーズン順位で決まる**（Immortal は上位500位、Radiant は上位100位。足りなければ Ascendant III）
- **MMR（内部レーティング）**：Elo（K=32。認定戦中は 64）。ユーザーには数値を返さない。初期値 1000
- **RP（ランクポイント）**：勝つと増え、負けると減る（相手との MMR の差で増減が変わる。勝ち 10〜40、負け 8〜30）。RP は 0 未満にならない。表示ランクは RP から決まるので、昇格・降格は RP がまたいだときに起きる（降格の保護はまだない）
- **認定戦**：最初の5試合（`placementMatches`）は RP が動かず、ランクは「認定戦中」。終わると MMR から RP とランクが決まる（Gold III までが上限）
- ランク戦の結果は、**ゲームサーバーが確定した試合の結果**から、経験値と**同じトランザクション**で反映する（`Ranking.applyMatch`）。クライアントがランクや勝敗を指定する口はない。同じ試合 ID は1回だけ

## シーズン（`data/seasons.json`）
- 起点（`epoch`）から `lengthDays`（56日）ごとに自動で番号が進む。`season_stats` にシーズン・モードごとの成績（MMR・RP・最高RP・試合数）が残る（`mode_id` は `kingdom`。将来の別モードは別の行＝独立ランクにできる）
- 新しいシーズンの最初の参加で、MMR を初期値に近づけ（差を半分）、短い認定戦（2試合）からやり直す。**前のシーズンの記録（最高到達ランク）は残る**
- シーズン報酬（到達ランクに応じた報酬の受け取り）は **Phase 6**

## マッチメイキング（`server/accounts/matchmaking.js`）
- **正会員（Google 連携かメールアドレスの登録）だけ**参加できる。ゲストは 403（`needsMember`）。CPU・ゲスト・カジュアル（合言葉）の対戦ではレートは動かない
- 待ち行列は**メモリだけ**（サーバーを再起動すると空。成立済みの試合は部屋ごと消える）。同じユーザーは1つの行列・1つの試合にしか入れない。進行中の別の試合がある間も並べない
- MMR が近い人を選ぶ。待つほど範囲が広がる（100 → 10秒ごとに +50 → 最大800）。90秒で見つからなければタイムアウト（案内を1回返す）
- 成立すると、サーバーが部屋（合言葉では入れない）・対戦 ID・席の鍵を決め、すぐ試合が始まる。先攻・後攻はランダム。デッキはクラウドの使用中のデッキ（コスト制の決まりに合えば）か見本のデッキ。鍵は本人に `GET /api/ranked/status` でだけ返す（**切断しても、ここから戻れる**）

## 不正対策
- 切断・部屋を出る・タブを閉じたまま戻らない（`disconnectGraceMs`＝90秒）は、**降参＝負け**（勝ち逃げ・負け逃れをさせない）。最初から誰もつながなかった試合（`connectGraceMs`＝60秒）は**無効**（レートは変わらない）。つながっているのに手を打たない（`idleTurnMs`＝180秒）のも降参
- ランク戦の部屋では、設定変更・CPU 追加・もう1回・部屋に戻るはできない
- **勝ち星の交換対策**：同じ相手との24時間以内の勝ちは、3回目まで満額、6回目まで半分、それ以降は RP 0
- 同じアカウントが2席・CPU・ゲストの試合は、レートが動かない。ランクの API はすべてサーバーが読むだけ（POST は相手探し・やめるだけ）

## 画面
- ホームの「ランクマッチ」「ランキング」が使える。ランク画面（`RankedView.js`）：エンブレム（`RankEmblem.js`。オリジナルの図柄）・RP・認定戦の進み具合・相手探し（待機時間・やめる・成立したら自動で試合に入る・タイムアウトの案内）・シーズンの記録。ゲストには連携の案内
- 結果画面：RP の増減・昇格/降格、認定戦の進み。「ランクマッチ画面へ」（同じ相手とのもう1回はない）。ランク戦の途中で「タイトルへ」を押すと、負けになる警告が出る（もう一度押すと抜ける）

## まだやっていないこと
- 降格の保護・ディビジョンごとの昇格戦、シーズン報酬の受け取り（Phase 6）
- 待ち行列を再起動をまたいで保つこと、複数台構成
- 本物の Google 連携で会員になった人どうしの確認（テストでは会員フラグをデータベースで直接立てている）
- 人数が少ないときの調整（待つほど範囲が広がる）は仮の数値。**実際の人数でチューニングが必要**

# Phase 4：フレンド・招待・パーティー・オンライン状態

フレンド情報（フレンド関係・ブロック・設定・フレンドコード）は**サーバーのデータベース**に保存する。招待・パーティー・オンライン状態は、短い間だけ意味があるのでサーバーの**メモリ**（再起動で消える）。

## 使える人
- **正会員（Google 連携かメールアドレスの登録）だけ**。ゲストは使えない（403 `needsMember`）。ゲストには送れない・検索にも出ない（アカウントが消えるとフレンドの意味がなくなるため）

## できること
- **プレイヤー検索**：名前の前方一致（2〜16文字）か、**フレンドコード**（8文字。自分のコードは「さがす」に出る）。自分・ブロックの関係にある人・「検索されない」設定の人は出ない（コードなら見つかる）。1分に20回まで
- **フレンド申請**：承認・断る・取り消し・削除。お互いに同時に申請したら自動で成立。フレンドは100人まで
- **オンライン状態**：`online`（直近75秒以内に画面がサーバーを読んだ）／`in_match`（試合中）／`offline`／`hidden`（本人が「見せない」設定）。画面がフレンドの状態を読むたびに、自分も「オンライン」になる。見えるのはフレンドだけ
- **対戦の招待**：フレンドに送る。サーバーが**合言葉**（`f-…`）を決め、招待を受けた人が「参加」したときに初めて渡す。招く側も受ける側も、その合言葉で**今までの合言葉ルーム**に入る（部屋の機能はそのまま使う）。有効期間2分・1回だけ・同じ相手への古い招待は置きかえ
- **パーティー**：作る → フレンドを招待 → 参加。リーダーが「対戦する」を押すと、サーバーが合言葉（`p-…`）を決め、**パーティーのメンバーにだけ**見える。メンバーがその合言葉の部屋に入り、リーダー（部屋主）が部屋の「開始」を押す。上限8人。リーダーが抜けたら次の人がリーダー、1人になったら解散。リーダーはメンバーを外せる

## 迷惑・スパム対策
- **ブロック**：フレンド関係・申請・招待・同じパーティーを消す。ブロックした人・された人は、お互いに申請・招待・検索ができず、プロフィールも見えない（404）。ブロックされたことは相手に伝わらない（送れないという文だけ）。解除できる
- 回数の制限：申請は1時間に10回、検索は1分に20回、招待は1分に6回。返事待ちの申請は20件まで。**断られたら24時間は同じ人に申請できない**
- **受けない設定**（本人が選べる）：フレンド申請・対戦の招待・オンライン状態の公開・名前検索への表示
- 申請・招待の相手は、自分のIDと、サーバーが調べた関係だけで決まる（他人の申請に返事する・他人のパーティーを操作することはできない）
- アカウント削除：フレンド・ブロック・申請はデータベースから消え、招待・パーティー・オンライン状態も消える
- プロフィールの公開設定「フレンドだけ」が、フレンドにだけ見えるようになった（Phase 2 の続き）

## API（Phase 4）
| メソッド・URL | 内容 |
|---|---|
| `GET /api/social/state` | フレンド（状態つき）・届いた/送った申請・ブロック・招待・パーティー・自分のコード・設定。呼ぶと自分が「オンライン」になる（画面は8秒ごとに読む） |
| `POST /api/social/settings` `{ settings }` | `acceptRequests` / `acceptInvites` / `showOnline` / `searchable`（真偽値） |
| `POST /api/friends/search` `{ q }` ／ `request` `{ userId または code }` ／ `respond` `{ userId, accept }` ／ `cancel` ／ `remove` | 検索・申請・返事・取り消し・削除 |
| `POST /api/block` / `unblock` `{ userId }` | ブロック・解除 |
| `POST /api/invites/send` `{ userId }` ／ `respond` `{ id, accept }` | 招待を送る（`{ id, passphrase }` を招く側に返す）／返事（受けた人に `passphrase`） |
| `POST /api/party/create` ／ `invite` `{ userId }` ／ `leave` ／ `kick` `{ userId }` ／ `start` | パーティー |

## 画面
- ホームの「フレンド対戦」→ フレンド画面（`SocialView.js`）：フレンド一覧（状態の印・タップで 招待／プロフィール／削除／ブロック。削除・ブロックは2回押し）、パーティー、申請（承認・断る・取り消し）、さがす（名前・フレンドコード・自分のコード）、設定とブロック一覧
- 招待・パーティーの部屋の知らせは、ホームにいるあいだ**バナー**で出る（8秒ごとに確認）。「フレンド対戦」のタイルと🔔に、申請・招待の数の印が出る。試合中は出ない

## まだやっていないこと
- **プッシュ通知**（画面を閉じている間の招待）。招待は画面を開いている間だけ届く（有効期間2分）
- 招待・パーティーの状態はメモリのため、サーバーを再起動すると消える
- 通報・運営への連絡、チャットの文のフィルタ
- パーティーでのランクマッチ（ランクは1人ずつ）
- 本物の Google 連携で会員になった人どうしでの確認（テストでは会員の印をデータベースで直接つけている）

# Phase 5：通貨・ショップ・ガチャ・スキン・所持品

景品は**すべて見た目だけ**で、ランクマッチの勝敗には影響しない。価格・確率・景品は `data/shop.json`・`data/gacha.json`（**数値はすべて仮**）。実際の決済・有料通貨・有料ガチャは**作っていない**（法務・決済・運営体制ができるまで追加しない）。

## 通貨（`server/accounts/economy.js`）
- **無料コイン**（`wallets.free_coins`）と**交換ポイント**（`exchange_points`）は別の列。将来の有料通貨は、さらに別の列にして混ぜない設計（今は存在しない）
- 増減はすべて**トランザクション**で、`coin_ledger` に記録する。`(ユーザー, 通貨, 理由, 参照)` が一意なので、**同じ報酬は二重に付かない**。残高は 0 未満にならない（DB の CHECK と事前の確認）
- 入手：対戦報酬（オンライン対戦。勝ち 20・負け 10、CPU 相手は半分、短すぎる・途中で抜けた試合は 0、**1日 300 まで**。`progression.json` の `matchCoins`）、レベル報酬。ミッション・シーズン報酬は Phase 6
- **ひとりで遊ぶ・同じ端末ではコインは増えない**（サーバーを通らず、申告を信じないため）

## ショップ・所持品・装備
- 種類（`slot`）：兵士スキン・城の外観・カード裏面・攻撃エフェクト・勝利演出（紙ふぶきの色）・プロフィールアイコン・称号。各景品に `world`（今は `kingdom`）があり、将来の別の世界（日本モード）のスキンを足せる。装備は `world` ごと
- 購入：`POST /api/shop/buy { itemId }` だけ（価格は送れない）。コインの減算・所持品の付与は1つのトランザクション。持っているものは買えない・足りなければ何も変わらない・ガチャ限定（`price: null`）は買えない
- 装備：持っているものだけ・スロットが合うものだけ。持っていない／なくなった景品は、標準の見た目にもどる
- **スキンの実装は色替え（CSSフィルタ）**。兵士・城は一度白黒にしてから色をつける（元の絵の色に関係なく単色になる）。**専用の絵は未作成**（作ったら `shop.json` に `image` を足せる）
- スキンは**対戦中の盤面に反映**：兵士・城・魔法/射撃のエフェクト・勝利の紙ふぶき。オンラインでは、席ごとの装備（`room.players[].cosmetics`。サーバーが、その人が持っているものだけを入れる）が**相手にも見える**。ひとりで遊ぶときは自分の装備。カード裏面は、ゲーム中にはカードの裏が出る場面が少ないため、いまは小さなカードのアイコンにだけ反映（見本はショップ・所持品に出る）
- アイコン・称号：装備するとプロフィール・ホームに出る（無料のアイコンを選ぶと外れる）

## ガチャ
- 1回 100・10連 900 コイン（`gacha.json`）。確率は 60/25/11/3.5/0.5%（コモン〜レジェンド）。**抽選はサーバーの安全な乱数**（`crypto.randomInt`）
- **抽選とコイン消費は1つのトランザクション**（原子的）。同時に何度押されても、残高の範囲でだけ成功する。履歴は `gacha_pulls`
- **救済**：エピック以上が40回出なければ確定（天井）。10連は**レア以上が1つ確定**
- **重複**：持っている景品は失わず、**交換ポイント**になる（コモン3・アンコモン8・レア20・エピック60・レジェンド150）。ポイントで、持っていないガチャの景品を選んで**交換**できる（コモン20〜レジェンド800）
- **排出率の表示**：`GET /api/gacha/info` がレアリティの割合と景品ごとの確率・救済の回数を返し、画面の「排出率・景品の一覧」に出す

## API（Phase 5）
| メソッド・URL | 内容 |
|---|---|
| `GET /api/shop` ／ `POST /api/shop/buy` `{ itemId }` | 景品の一覧（持っているか・装備中か・買えるか）／購入 |
| `GET /api/collection` ／ `POST /api/collection/equip` `{ slot, itemId \| null }` | 所持品と装備／装備・外す |
| `GET /api/gacha/info?banner=` ／ `POST /api/gacha/pull` `{ banner, count: 1\|10 }` ／ `POST /api/gacha/exchange` `{ itemId }` ／ `GET /api/gacha/history` | ガチャ |
| `GET /api/wallet` | 残高と、直近の出入りの記録 |

## 画面
- ホームの「ショップ」「ガチャ」「スキン」が使える。`CollectionView.js`：ショップ（種類ごとの見本つき）・ガチャ（1回/10連・レアリティで派手になる結果の演出・タップで飛ばせる・排出率・交換・履歴）・所持品（装備/外す）。結果画面に獲得コイン
- ゲストも使える（連携するとデータは引き継がれる）。ゲストのままだと、ブラウザのデータを消すとコインも景品も戻らない

## まだやっていないこと
- スキンの専用の絵（いまは色替え）。カード裏面のゲーム中の表示場面
- 期間限定のガチャ・ピックアップ・天井の持ちこし、景品の売却・譲渡（意図的に作らない）
- 有料通貨・決済（この段階では対象外）
- 日本モード用の景品（`world` の仕組みだけ用意済み）

# Phase 6：ミッション・シーズン報酬・運用・データ保護・日本モード（世界）の基盤

## ミッション（`server/accounts/missions.js`、データは `data/missions.json`・仮）
- 種類：**デイリー**（プールから日付で決まる3つ。全員同じ）・**ウィークリー**（4つ）・**シーズン**（3つ）。期間の区切りは**日本時間**（デイリーは毎日0:00、ウィークリーは月曜0:00、シーズンは `seasons.json` に従う）
- 例：対戦を1回完了する／対戦に3回勝利する／カードを5回合成する／魔物を3体倒す／ランクマッチで勝つ
- **進み具合はサーバーが数える**：確定した試合の結果（戦績・勝敗）と、サーバーが見たゲームのイベント（`cardsFused`・`monsterDefeated`）から。クライアントが「達成した」と送る口はない。戦績に数えない試合・人（自分どうし・途中で抜けた など）は数えない。**ひとりで遊ぶ・同じ端末は対象外**（サーバーを通らないため）
- **報酬の受け取り**（`POST /api/missions/claim`）：達成済みで未受け取りのものだけ。コインの加算と「受け取った」の記録が1つのトランザクションで、コイン台帳の一意制約（`mission` + `ミッションID:期間`）で**二重受け取りを防ぐ**（同時に押しても1回）。期間が終わると受け取れなくなる（受け取らなかった日・週のミッションは消える）

## シーズン報酬
- 終わったシーズンについて、**最高到達ランク**に応じたコイン（`seasons.json` の `rewards`）。条件：認定戦が終わっていて、ランク戦を `minMatchesForReward`（5）試合以上。今のシーズンは対象外。1回だけ（`season_rewards` の主キー＋台帳）
- 受け取り履歴は `coin_ledger`（理由：`mission`・`seasonReward`・`levelReward`・`match`）。`GET /api/wallet` で直近の出入りが見える

## ランキング
- 今のシーズンのランキング（`GET /api/ranking`）は Phase 3 から。認定戦が終わった人だけ・同点は MMR の高い順（MMR は返さない）・「ランキングの名前」を非公開にした人は匿名

## モード（世界）の基盤（`data/modes.json`）
- 王国（`kingdom`。いまの遊び）と、日本の戦国・和風ファンタジー（`japan`。**準備中**・`available: false`）の一覧。**日本専用のカード・ルールは別工程**で、ここでは仕組みだけ
- **共通**：アカウント・プレイヤーレベル・通貨・所持品。**モードごとに別**：デッキ（`user_decks.mode_id`・`user_deck_settings`）・戦績（`matches.mode_id`）・ランクとシーズンの成績（`season_stats.mode_id`。独立ランクにできる）・景品の `world`・装備の `world`
- `GET /api/decks?mode=` ほか、デッキの API は `mode`（省略すると王国）を受ける。使えない世界は 400。`GET /api/modes`：一覧と、自分のモードごとの戦績・ランク。ランクマッチの `mode` が使えない世界なら 400（`modeUnavailable`）
- 画面：ホームに世界の切り替え（王国／戦国（準備中）。準備中は押せない）
- データベースの移行 6：既存のデッキと「使っている枠」は**王国として残る**（移行のテストあり）

## 運用（`server/ops.js`）
- **ログ**：JSON 1行（`CF_LOG_LEVEL`：debug/info/warn/error。`CF_LOG=off` で止める）。リクエストは**パスの形・状態・時間だけ**（`GET /api/profile/user/:user`）。**問い合わせ部分（`?token=`）・ヘッダー・本文・IP・ユーザーIDは残さない**。5xx は error、1.5秒より遅いものは warn。想定外のエラーは構造化して出す
- **稼働確認**：`GET /healthz`（動いているか）・`GET /readyz`（データベースにも触れる。失敗なら 503）。詳細は出さない
- **メトリクス**：`GET /metrics`（Prometheus 形式。リクエスト数・応答時間・部屋の数・ランクの待ち人数・有効なセッション・ユーザー数）。`CF_METRICS_TOKEN` があれば `Authorization: Bearer` が必要、なければ **localhost からだけ**
- **定期の掃除（毎時）**：期限切れのセッション・認証の途中経過・古いミッション・90日より古い監査ログを消す
- **自動バックアップ**：`CF_BACKUP_DIR` を決めると、`CF_BACKUP_INTERVAL_HOURS`（既定24）ごとに作り、`CF_BACKUP_KEEP`（既定7）世代だけ残す（復元は `node server/backup.js restore`）
- **再起動の安全**：データはすべてデータベースにあり、再起動で消えるのは「ランクの待ち行列・招待・パーティー・オンライン状態」だけ（画面は探し直し・招待し直しになる）。試合中の部屋はメモリなので、再起動すると試合は中断される（**未対応**）

## データ保護
- **データの書き出し**（`GET /api/account/export`。画面は「アカウント」→「データを書き出す」）：自分のアカウント・プロフィール・戦績・デッキ・ランクの記録・通貨と出入り・所持品・ガチャ履歴・ミッション・フレンド/ブロックの名前を JSON で。**他人のID・MMR・ログイン用の鍵は含めない**。1時間に3回まで
- **削除**：`POST /api/account/delete`。個人に結びつくデータはすべて消える（外部キーの連鎖。通貨・所持品・ガチャ履歴・ミッション・フレンド・ブロックを含む）。相手の戦績に残る自分の名前は「（削除済み）」に。監査ログにはハッシュ化したIDと「削除した」という事実だけ
- メールアドレスは預からない。IP・端末は保存しない

## まだやっていないこと・限界
- 試合中の部屋の永続化（再起動で試合は中断される）。複数台・負荷分散
- 通報・運営用の管理画面。ログの外部送信・アラート
- Google の本物との通信、実機・本番での確認
- 日本モードの中身（カード・ルール・城・背景）。モードごとの `cards` の切り替えは未実装（`Room` は今は王国の `data` だけを使う）
- ミッションの追加・期間限定（データの追加だけで増やせる）
